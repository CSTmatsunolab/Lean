担当の回は、MIL の該当する節を読んで、ほかの参加者に説明します。
目安は 1 回 90 分で、そのうち説明 40 分、演習 40 分、まとめ 10 分です。

## 準備すること

1. **該当する節を読み、Lean ファイルの例題を動かす**
   - 当日扱う必須の例題・演習は、教員と相談して前もって決めます。まずはそれを優先してください
   - 1 行ずつカーソルを動かして、Infoview のゴールがどう変わるかを確認する
2. **新しく出てきたタクティクと定理をまとめる**
   - 例: 「`rw [h]` はゴールの中の `h` の左辺を右辺に書き換える。書き換えた結果、両辺が同じ形になればゴールは自動で閉じる」
3. **演習を解く**
   - 解けなかった問題は「どこで詰まったか」を説明できれば OK。全員で考えます
   - 解答は各章のフォルダの中の `solutions` にあります（例: `MIL/C02_Basics/solutions/Solutions_S01_Calculating.lean`）。自分で考えてから見てください
4. **説明用の資料を作る**
   - VS Code の画面を映しながら説明するのがおすすめです。スライドは任意です

## 当日の流れ

1. この節で何を証明するのか（数学的な内容）を、紙の上の証明で説明する
2. 同じ証明を Lean で書くとどうなるかを、ゴールを見せながら説明する
3. 新しいタクティクのまとめ
4. 演習を全員で解く（担当者はヒントを出す役）
5. わかりにくかった点、詰まった点を共有する

## 書き方のヒント

- ゴールが複雑になったら `have` で途中の主張を作って分けて考える
- 使いたい定理の名前がわからないときは、`exact?`・`apply?` や [Loogle](https://loogle.lean-lang.org/)、[LeanSearch](https://leansearch.net/) で探す
- Mathlib の定理の名前には規則があります（例: `mul_comm` は「掛け算の交換法則」）。[命名規則](https://mathlib.org/contribute/naming.html) を一度眺めておくと探しやすくなります
- [タクティクのチートシート (PDF)](https://leanprover-community.github.io/papers/lean-tactics.pdf) を手元に置いておくと便利です
